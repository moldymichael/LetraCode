# 4-bit QLoRA implementation plan

**Goal:** Add a usable, verified low-memory training option to the installed LetraCode app and update its existing GitHub change.

**Architecture:** Keep the separate offline training process and immutable run snapshots. Add explicit CUDA QLoRA alongside backward-compatible full-precision LoRA. The desktop runtime remains independent of the training Python.

**Tech stack:** PySide6, PyTorch, Transformers, PEFT, bitsandbytes, llama.cpp.

## Configuration and interface

- `training_method`: `lora` for missing legacy fields, or `qlora` requiring CUDA.
- `gradient_accumulation_steps`: integer 1–128, legacy default 1.
- `gradient_checkpointing`: boolean, legacy default false.
- New UI defaults: QLoRA, CUDA, microbatch 1, accumulation 4, checkpointing on, rank 8, length 512. Preserve saved legacy configurations.
- QLoRA loads original local text-only Llama safetensors into NF4 with double quantization. Explicit single-GPU placement; native BF16 when supported, otherwise FP16. Frozen base, all-linear adapters, prompt-masked loss, token-weighted accumulation including partial final groups.
- Reports record method, quantization, compute precision, trainable and quantized layer counts, effective batch, and actual CUDA memory. Compare the same quantized base before and after optimization.
- Preserve local-only model loading, approved datasets, GGUF conversion, explicit adoption/rollback, two-model conversations, thinking, and user data.

## Execution

- [x] Config/UI: tests for invalid QLoRA settings, legacy compatibility, persistence and report display; implement controls and training-environment discovery.
- [x] Backend/worker: failing tests for native dtype selection, quantized load requirements, accumulation equivalence and final partial groups, report validation; implement NF4 training and actionable CUDA/dependency/memory errors.
- [x] Runtime/proof: create a separate CUDA Python environment without replacing desktop dependencies. Extend the generated-model verification tool and run real GPU optimization, GGUF conversion, adoption, inference and rollback. Compare identical generated weights in full precision and QLoRA.
- [x] Release: update version, dependency manifest and setup docs; run complete regressions and package checks; obtain independent review.
- [x] Installed app: preserve previous installation and data, close through the normal app shutdown path, install the verified source, inspect the installed UI against copied data, and reopen the actual launcher.
- [x] GitHub: commit verified changes, push the existing feature branch and update PR #7 with final scope and evidence.

## Verification boundary

A generated tiny model proves optimization and integration, not useful assistant quality. QLoRA reduces weight memory but cannot guarantee that any particular real model fits this 8 GiB GPU or improves its answers. Original safetensors are required; a GGUF inference file cannot be trained directly.

The implementation follows the [Transformers bitsandbytes guide](https://huggingface.co/docs/transformers/quantization/bitsandbytes), [PEFT quantization guide](https://huggingface.co/docs/peft/developer_guides/quantization), and [bitsandbytes hardware requirements](https://huggingface.co/docs/bitsandbytes/installation).
