# Conversation training upgrade

The requested upgrade makes a reviewed example a complete, text-only conversation with available function-tool definitions. The canonical version-2 record has `schema_version: 2`, ordered `messages`, and `tools`. Messages use `system`, `user`, `assistant`, or `tool`; assistant messages can contain OpenAI-style `tool_calls` and a boolean `train` flag (default true). Function arguments are JSON objects. Tool results refer to unique call IDs. Every call must have exactly one result before further conversation. Recorded tools are data and are never executed.

Keep legacy prompt/response save calls, imports, drafts, and immutable run snapshots readable. Additive storage retains the old columns as summaries, with structured JSON as the authority for new records. All imports are drafts. Content, tool schema, call linkage, supervision, and split edits invalidate approval. Imports are atomic; invalid records have actionable message/line errors. Sequence validity does not impose artificial user/assistant alternation. Unsupported roles, non-text payloads, malformed arguments, unmatched calls, and examples without assistant targets are rejected.

The editor starts with user and assistant cards. Users can append, reorder, and remove messages, edit calls and tool schemas, link results, collapse long tool results, and mark assistant turns context-only. Draft recovery retains unfinished structured edits, including invalid JSON. The review interface shows the entire conversation and what is learned.

Training and preparation use one encoder and the selected local tokenizer's native template, including its tool template and tool definitions. Full sequence tokens must remain intact. Verified generation-prefix boundaries identify each assistant's target span; tool-free native assistant masks can be used only with equivalent verification. Fail closed if the native template drops fields, rewrites earlier spans inconsistently, lacks tool support, or cannot prove loss boundaries. User, system, tool, and context-only assistant tokens are masked. EOS/end-of-turn tokens belonging to a target assistant are trained. Overlong records fail before model loading; no slicing, fallback templates, or replay of recorded tools.

Frozen training/evaluation datasets preserve structure and supervision. Held-out loss uses all target assistant spans. Generated previews and candidate comparison use a clearly identified held-out target and its full prior context/tool definitions, without executing tools. Provenance retains template and dataset evidence. Existing adoption, conversion, rollback, and platform safeguards remain in force.

Verification includes legacy migration and snapshot compatibility, structured import/export round trips, approval and draft recovery, call/result validation, real tokenizer masks and template rejection, sequence overflow, Qt editing, and an actual tiny-model optimization through the production backend. Native Windows and full-size model training are reported separately if unavailable. This task prepares a focused branch and draft PR; teammate approval and required CI gate integration, and releases/live data migration are outside scope.
